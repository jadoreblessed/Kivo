# KIVO implementation status

The portable package can create a fixed-supply Token-2022 mint through the user's wallet on devnet or mainnet. It stores name and ticker onchain, optionally stores a metadata JSON URI, creates the creator's token account, mints the full supply, and revokes mint authority. The token's mint address is its CA.

The admin route can persist a verified mainnet token mint address and an X profile using an external Redis REST database. It requires the four server environment values documented in `.env.example`; admin functions cannot work without these values. CA publishing is distinct from mint creation.

The deployed public site still shows an older build. In this source tree, the launch, trading, graduation and market catalogue pages are wired to the onchain program when its program ID, network and treasury are configured. The onchain program has only been run on a local validator. It is not deployed to devnet or mainnet. Browser wallet flows still need a live cluster rehearsal and an independent security review before any real funds flow through a market.

## Contract work in progress

`programs/kivo-market` now contains a **local prototype** for market initialization, buys, sells, claims of accrued creator and treasury trading fees, atomic migration into a permanently locked Meteora DAMM v2 position, and collection of post-migration pool fees. The pool swap fee is fixed at 1% in the tested build, with Meteora's protocol share applied by DAMM. The remaining collectible SOL fee splits by the creator percentage chosen at launch (0–80%, 50% default); the rest goes to the KIVO treasury. `programs/kivo-market-math` contains integer quote calculations for the five rules and ten price tranches. Six math tests pass. The program has passed local validator tests for mint authority revocation, buying with burn, pot payout, guard rejection, selling, fee claims, the full-curve migration, an actual Meteora swap, and post-migration fee collection and claims, including a configured 65/35 split. The graduation test checks pool token and SOL balances, the position NFT owner, zero unlocked liquidity, the exact permanently locked liquidity and source account cleanup. The example program ID is not a production deployment.

The source now also includes up to four immutable creator fee recipients, onchain blueprint publication and a royalty of 0–10% of LP/pot contributions. The UI can select published rules, and the program reserves accrued royalties during pool migration for the blueprint author to claim. The onchain program fixes the treasury public key at build time and rejects attempts to substitute another address. On 2026-10-04 the **current** KIVO program and pinned Meteora program compiled as SBPFv0 with cargo-build-sbf 4.4.0. Seven math tests passed. The local validator passed mint/buy/sell/burn/fee claims, metadata mint+market creation, refusal of a substituted treasury, blueprint publication/accrual/migration reserve/claim, and the complete graduation test: locked position, real DAMM swap, collection of pool fees, 65/35 pool fee split, creator multiwallet claims, and blueprint author royalty claim.

It cannot safely be deployed for real trading yet: the RPC market catalogue is not a scalable indexed database; wallet transactions have not been rehearsed on devnet; and the trading program has not had an independent security review. The Meteora ABI is pinned to local upstream commit `a85c926607433f23f0ea60f4ca7b1ae92f4156cb` and needs deployment-version validation against the actual target cluster. Graduation burns under 0.01% token rounding dust; under 0.01% SOL rounding dust and source-account rent go to the permissionless graduation caller. **The previous handoff archive does not include this prototype and should not be deployed as a trading protocol.**

Checks: TypeScript and build pass in the local sandbox on 2026-10-04. The combined blueprint → Meteora migration → pool swap → fee claim test passes locally. Wallet/devnet and mainnet transactions, deployed admin persistence, and a browser end-to-end flow have not been verified here. Do not present local validation as a security audit or mainnet launch.
